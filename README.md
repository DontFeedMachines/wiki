# Don't Feed Machines / Wiki

the build wiki behind dontfeedmachines.com. it is a documentation site for
counter-surveillance and privacy hardware you can actually make: rf security,
acoustic defense, visual evasion, hardware access, opsec. each project is a
markdown page with a parts list, a build, and the reasoning for why the thing
works. this repo is the site, not the projects. the projects live in
`src/content/docs/projects/`.

built on [Astro](https://astro.build) + [Starlight](https://starlight.astro.build),
on top of the DocKit theme. deploys to Cloudflare Workers as static assets.

## running it

pnpm only here. not npm, not yarn, no matter what the theme docs say. if a
snippet somewhere says `yarn dev`, it means `pnpm dev`.

```bash
pnpm install
pnpm dev
```

that puts the site at `http://localhost:4321`. dev has hot reload, so you edit a
markdown file and the page updates while you watch it.

the rest of the commands, run from the repo root:

```bash
pnpm build      # production build into ./dist
pnpm preview    # serve the built ./dist locally before you ship it
pnpm check      # astro's typecheck, run it before a deploy
```

## writing a project page

a project is one markdown file under
`src/content/docs/projects/<category>/<slug>.md`. the categories that exist
right now are `rf-security`, `acoustic-defense`, `visual-evasion`,
`hardware-access` and `opsec`. drop a new file in the right folder and it shows
up in the sidebar on its own, because that section is set to autogenerate.

every page starts with frontmatter:

```markdown
---
title: RFID Zapper
description: kills the chip in a contactless card by frying its coil.
---
```

the `title` is what people see in the sidebar and the tab. the `description` is
what search and link previews read, so write it like a real sentence, not a
keyword salad.

want a page higher up than alphabetical? name it explicitly in
`src/config/sidebar.json` before the autogenerate entry, the way Smart Dust
Sweeper is pinned there now. everything you do not name falls in after it,
sorted by filename.

## where the knobs are

nearly all of the site config is json under `src/config/`, so you rarely touch
`astro.config.mjs`. the ones you will actually open:

1. `config.json` holds the site title, the logo, the footer copyright and the
   Get Started button. the title reads "Don't Feed Machines | Wiki" and the
   footer credits svde. leave the pipe in the title, starlight splits on it.
2. `sidebar.json` is the whole left nav. groups, pinned pages, autogenerated
   directories, all here.
3. `social.json` is the icon links in the header. right now that is the
   [DontFeedMachines GitHub org](https://github.com/DontFeedMachines).
4. `theme.json` and `src/styles/global.css` are the look. color, spacing, the
   overrides.
5. `locals.json` is the language setup if the site ever goes multilingual. it is
   wired for it and not using it yet.

custom components (Grid, NewCard, Button, Accordion and the rest) live in
`src/components/user-components/` and get imported into an `.mdx` page when a
plain markdown table will not do. the starlight overrides in
`src/components/override-components/` are the header, footer, hero and sidebar,
already customized. change those carefully, they render on every page.

## structure

```
src/
  assets/         images and the logo
  components/
    override-components/   customized starlight internals
    user-components/       DocKit's own components
  config/         all the json config
  content/
    docs/         every page. projects/ is the meat
    i18n/         ui strings
    sections/     reusable page blocks
  styles/         global css
astro.config.mjs  wires the config json into starlight
wrangler.jsonc    cloudflare workers deploy target
```

## shipping it

the site is static, so a build is just files in `./dist`. deploy target is
Cloudflare Workers with static assets, configured in `wrangler.jsonc`:

```bash
pnpm build
pnpm dlx wrangler deploy
```

build first, always, because wrangler ships whatever is sitting in `./dist` and
does not build for you. want to see exactly what workers will serve before it
goes live? `pnpm build` then `pnpm dlx wrangler dev`.
