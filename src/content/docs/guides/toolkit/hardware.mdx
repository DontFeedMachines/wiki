## HOW AN ENTRY IS LAID OUT

1. the claim: what it stops or detects, in one paragraph.
2. the at-a-glance table: parts count, cost, skill level, whether it needs firmware.
3. the parts list.
4. the build, as numbered steps.
5. the test: how you confirm it works against the thing it claims to stop.

## USING ONE

<Steps>

1. pick the entry that matches the threat.
2. buy the parts from the list. nothing in an entry requires an account or a proprietary part.
3. solder it, following the [Build Guides](/guides/builds/).
4. flash the firmware if the entry has any: [Firmware Overview](/guides/toolkit/firmware/).
5. run the test at the bottom of the entry. if it fails, the entry's troubleshooting section comes first, then reopen the build.

</Steps>
